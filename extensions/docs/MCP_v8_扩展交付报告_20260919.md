## 二、并行与作业编排（G1）

1. `submit_job` 契约扩展为 6 参：新增 `numWorkers / gpu / attachedFiles`；`mcp_submit_job_core` 相应支持 `AttachedFiles`、`NumWorkersRange`，并把 `gpu` 透传给 worker。
2. `mcp_job_runner` 现在**显式打出静默降级的真相**（实测已在 run.log 出现）：
   `pool: none. WARNING - parfor inside this function runs SERIALLY (measured parfor 12.18 s vs serial 12.11 s for 12x pause(1)), and a worker cannot start its own pool (parallel:cluster:PoolRunValidation). For throughput submit several one-worker jobs (use submit_sweep).`
   另加 worker 出身信息 `worker: host=... user=... cores=16`。
3. **多参数 API 可进了**：`mcpCall` 展开机制。实测
   `submit_job(... '{"cfg":{"a":7,"unit":"keV"},"mcpCall":["$cfg","N",10,"Seed",3]}' ...)` →
   worker 内打印 `callform a=7 unit=keV varargin=['N' 10 'Seed' 3]`，`status:"finished"`。
   这解掉了"文档里的 `tepc.run.execute(cfg,"N",1e5,"Seed",12345)` 形状无法提交"的硬约束。
4. 新增 `submit_sweep / sweep_status / cancel_sweep`：一次提交 N 个参数集并登记 sweepId；
   实测 `sweepId=sweep_20260919_133141_3708 planned=3 submitted=3 skipped=0`，
   `sweep_status` 输出 `SUMMARY finished=3 failed=0 ... 3/3 terminal` + `compute: total=3.7s median=1.22s`；
   长跑扫描 `cancel_sweep` 先 `DRY RUN`，`confirm="yes"` 后 `cancel=2/2`。
   `sweep_status` 刻意只读 `meta.json/done.json`，不碰 cluster 句柄（避免"作业日志可能不完整"警告污染）。
5. `list_jobs` 从"全量倾倒"变成可过滤：实测 `list_jobs('','5','')` → `5 listed of 26 matching jobs | all states: finished=24 failed=1 cancelled=1`，`list_jobs('failed',...)` 精确命中 1 条。

## 三、Simulink 层（G2）

- 新增 `sl_sim(modelPath, simTime, paramJson, outDir, keepInSession)`：先 `load_system('simulink')`（实测不加载时 `find_system` 0 命中、`add_block([])` 只报 `Simulink:Commands:InvSimulinkObjHandle`），再建模参数注入、仿真、按 To Workspace 块**连同时间轴**取回信号，写 CSV 并在 base 里留 `<name>__t/<name>__y`。
  实测：`set_param: applied=2 failed=0 / sim: 0.300 s / simout n=301 t0=0 dt=2e-07 end=6e-05 mean=0.0531267 min=0 max=0.186914`。
- 新增 `sl_compare(aRef,bRef,tolJson,maxShift)`：**先做整数平移搜索再判门禁**。实测（同一模型、同一系数、MATLAB `filter` 对照）：
  ```
  at shift 0  : max_abs=9.5163e-02 peak_rel=8.9e-16 area_rel=2.9228e-03
  best shift -1: max_abs=3.0809e-15 peak_rel=8.9e-16 area_rel=4.9144e-15
  DIAGNOSIS the traces are offset by -1 sample(s) (-2e-07 s); removing it improves max_abs from 9.516e-02 to 3.081e-15
  GATES sample<=1e-09:1  peak<=0.001:1  area<=0.001:1 -> PASS
  ```
  ——这正是上一轮"0.54% 假失败"的根因，现已由工具自动定位并通过。
- 返工记录：`sl_compare` 首版有两处缺陷（`zero` 未初始化导致 `UndefinedFunction 'zero'`；`__y→__t` 名字裁剪少了一位导致 `noOverlap`），都已修并复测；另外它曾在指标跨平移几乎不变时仍宣称"是记账错位"，已改为**只有当平移带来 ≥100× 改善才下此结论**，否则明确输出 `this is a real signal difference, NOT a logging offset`。
- 未做（受本机限制，非工具缺口）：`Simulink.sdi` 脚本 API 在本机不可解析，故 SDI 路线未实现；`sl_build`（从 JSON 规格自动 new_system/add_block）未做，理由见第五节。

## 五点五、追加：`sl_build` 已实现（推翻第五节第 2 条的"暂缓"）

报告初稿把 `sl_build` 列为"收益低于成本、暂不做"。复核后认为它属于"能做到"，所以补做并测完，第五节第 2 条作废。

新增 `sl_build(modelPath, specJson, optsJson)`：从 JSON 规格搭模型 —— 块可用 `lib` 真实路径或 `type`（内部 `find_system` 解析）、支持位置、逐块 `set_param`、连线、模型级求解器参数；规格里的问题**收集后统一报告**而不是中途崩掉。两条实测坑被封进实现：库未 `load_system('simulink')` 时 `find_system` 返回 0 命中、`add_block([])` 只报 `Simulink:Commands:InvSimulinkObjHandle`；真实块路径是 `simulink/Sinks/To Workspace`，而 `simulink/Commonly Used Blocks/To Workspace` 不存在。

契约登记：`qa tools=11 sigs=11`（node 校验通过，`total extension tools` 由 26 增至 27）。

- 正向实测：`model: tepc_b (new) / block SRC <- simulink/Sources/From Workspace / block CPA <- simulink/Discrete/Discrete Transfer Fcn / block LOG <- simulink/Sinks/To Workspace / blocks added: 3 / lines connected: 2 / model parameters set: 6 / saved tepc_b.slx (72,237 bytes) / VERDICT: built clean`；随后 `sl_sim` → `sim: 0.106 s`、`simout2 n=301 t0=0 dt=2e-07 end=6e-05 mean=0.0531267`。
- 负向实测（故意写一个不存在的块类型）：`PROBLEMS (2): X: block source unresolved` 与 `line X/1->Y/2: Simulink 对象名称无效: 'X/1'`，输出 `VERDICT: built with 2 issue(s); fix the spec and rerun`，不崩、不假成功。
- 顺带修掉一个输出缺陷：`find_system` 返回的库路径在块名空格处带一个换行（打印成 `simulink/Sources/From\nWorkspace`），Simulink 能接受但人/agent 复用时会以为路径坏了 → 打印端已展平（`sl_build.m` 注释记录了这条）。
- 一次**有价值的真实判定**：我自己在 spec 里把系数写成 7 位小数 `'0.0951626'`（而非 `mat2str` 的全精度值），`sl_compare` 于是给出 `best shift -1: max_abs=3.2639e-08 peak_rel=1.5834e-07` 并在 `sample<=1e-9` 上判 **FAIL**；而上一轮用全精度系数时同一对比是 `max_abs=3.0809e-15 → PASS`。两条合起来证明该门禁既能吸收纯记账错位（−1 样本平移被识别并写明"bookkeeping not physics"），又不会被"看起来一样"的系数糊过去。
