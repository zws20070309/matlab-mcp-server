## 三、这一轮新发现的 3 个问题（已当场修 + 记录）

1. **`ver()` 在 R2025a 没有 `Folder` 字段**（`无法识别的字段名称 "Folder"`）。`resolve_capability` 里"归属到产品"的那段代码一直在拿不存在的字段比，靠 try/catch 静默降级成"outside ver().Folder"。已改为如实表述：归属只声明到 toolbox 目录段，并写明"本发行版 ver() 不暴露 Folder，故不做产品名映射"。缺失函数的**产品+许可**判定不受影响（走内置别名表 + `license('test')`），实测正确。
2. **`env_report` 的 java 行会说谎**：`version('-java')` 在懒启动前返回 "Java is not enabled"，而同一函数下面"digest 可用"又是真的（一次 `javaMethod` 就把 JVM 起来了）。已改为实际探测可用性再打印。
3. **`@@NL@@` 不能用在单引号字符串内部**：MATLAB 不允许 char 字面量里含真换行，`'...@@NL@@...'` 展开后变成未闭合字符串。本轮我自己踩了两次，第一次还被 `mcp_code_arg` 的 `multilineStripped` 守卫拦下（守卫本身工作正常，并给出了正确建议）。可行写法：串间换行用 `@@NL@@`，串内换行用 `newline`/`char(10)` 或干脆用 `disp`。这条建议要补进工具描述。

## 四、仍然存在的限制（不是本轮遗漏，而是本机/架构边界）

- GPU 只在**每进程开启前向兼容后**可用，且首次调用要付 JIT 重建（本机磁盘缓存命中时 0.6 s，冷缓存 MATLAB 自述"可能几分钟"）。
- worker 内不能起池、`parfor` 静默串行 → 扩核只能靠多作业（已由 sweep 系列工具支持）。
- 共享会话仍不可重开引擎；内存不还 OS（本轮：几次 GPU+仿真后 `used` 从 2.20 涨到 9.04 GiB，`session_reset` 卸掉 7 个模型后仍 9.04 GiB）。
- `get_variable mode=json` 对 300 点轨迹输出约 8 KB 且保留全精度浮点；超 30 KB 自动落盘只回摘要+路径。若想进一步瘦身可在 `jsonencode` 前做有效位截断（本轮未做，属可优化项而非缺陷）。
- Go 层原有 5 项限制不变（换行剥离根因、`evaluate_matlab_code` 输出头截断约 44 KB、`check_matlab_code` 单文件+snake_case、首调 `-32603`、`run_matlab_test_file` 多余 `ans`）。
