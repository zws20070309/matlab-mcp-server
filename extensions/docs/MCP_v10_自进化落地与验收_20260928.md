## 4. 返工中改掉的实际缺陷

1. `mcp_walk` 对嵌套树发现 0 个文件（`dir(fullfile(root,pattern))` 不返回目录，因此从不递归）——
   这会让任何真实认证静默"0 个测试"判成绿。改为两趟：本层按 pattern 收文件，另对 `dir(root)` 的每个非隐藏子目录递归。
   同时修掉 `code_refresh` 的 "scanned 0 .m file(s)"。
2. `strsplit(r, [filesep() '/'])` 把整个字符向量当成一个字面分隔符 `"\/"`，从不切分 → 分片优先级全同、
   顺序不按 unit/golden/integration/regression 排。改为 cell `{filesep(), '/'}`。
3. `docsync` 用子串匹配，README 写 572、counts 写 5 时判"已同步"。改为独立数字正则 `(?<!\d)5(?!\d)`。
4. `suite_status` 的 runId 切片只认 `END|`，完整运行被读成 `done: 0 / verdict NONE`；失败行提取用前缀正则把 `sec=3.1|` 留在诊断里。
5. `struct('docs',{...})` 展开成 2 元素结构体数组，`s.docs` 变逗号列表，报错却是 `isempty 输入参数太多`。
   改标量结构体 + 显式 `badStepArray` 报错。
6. `tests(char)` 不存在 → 用 `matlab.unittest.TestSuite.fromFile`；`TestResult` 无 `Data/Errors`，诊断走 `Details.toArray().Message`。
7. `onCleanup` 与显式 `fclose` 双关闭抛 `MATLAB:FileIO:InvalidFid`；相对路径用 `exist()` 解析会命中整个 matlabpath（2600+ 项）
   而把 `tools` 解析到别处 → 新增 `mcp_repo_path` 按形状判绝对/相对。
8. `longrun_preflight` 的注册描述与实际参数不符（写了未实现的 `warnOnly`），文档说谎 → 描述改成真实 schema，
   并把 `testsDir` 真正接上（缺 tests 目录成为 NO-GO 理由）。
9. 收尾清理告警时用一个空 `new_string` 的批量替换，把 `suite_status.m` 五处行尾换行吞掉，制造出 5 个解析错误；
   已按原结构逐行恢复并复验（该文件 `error=0`，全套件重跑通过）。

## 5. 边界与遗留（不猜，明确说）

- 5 个新工具的 schema 需要重启 MATLAB MCP 进程才会出现在会话面上：本轮 `mcp_list` 关键字 `suite` 只返回 `run_tests`，
  即当前会话仍看不到 `suite_run`。在此之前，工具可由 `evaluate_logged` 的 `codeFile` 入口驱动（本轮就是这样验收的）。
- `code_refresh` 能清缓存的仅限普通函数；`+pkg/` 与 `@class/` 仍需显式 `clear functions`，工具输出里已把这句话打出来，不假称全覆盖。
- 认证只证明"该树在该次运行内未变 + 两道账对齐"，不证明测试自身语义正确。
- 剩余 37 条 warning 全在 v8 及更早文件的既有风格项（`now` 用于 UTC 时间戳、防御性初始化、`isdir`→`isfolder`）；
  v10 新文件里保留的是刻意的初始化（`v = []`、`tf = false`，去掉会引入未初始化风险）。
- 夹具与配方留在 `extensions/v10_fixture`、`extensions/snippets/v10`（含日志目录），因为它们是这三条判据的复跑载体；
  如不需要可整目录删除，不影响任何工具。
